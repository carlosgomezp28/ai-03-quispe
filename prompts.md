# Part B — Economic question and mechanism

## 1. Central economic question

Does agentic coding AI expand the set of programming languages in which an individual developer can produce and ship code, rather than merely increasing productivity inside languages the developer already knows?

The paper’s central distinction is therefore:

- **Intensive margin:** more or better output in already feasible languages.
- **Extensive margin:** entry into previously infeasible or previously unused languages.

The object is explicitly a **production frontier**, not a human-skill frontier. See printed pp. 1–2 and Remark 1, pp. 14–15.

## 2. Core terminology

**Language frontier**

The set of languages in which a developer can profitably deliver working code using the best production mode available to her.

**Unfamiliar language**

In the model, a language with low language-specific execution skill and low precision about the developer-language productivity match. Empirically, it means a language absent from the developer’s previously observed public GitHub contributions. The authors explicitly warn that this need not mean zero private experience. See p. 11.

**Language-specific entry threshold**

The minimum opportunity value \(\theta_{ikt}\) required to make production in language \(k\) worthwhile for developer \(i\) at time \(t\). Costs, weak language knowledge, risk, and verification difficulty raise this threshold.

**Conversational AI**

A Generation-1 tool that suggests code, explains errors, or provides snippets, but leaves execution, integration, running, and debugging with the developer.

**Agentic AI / agentic delegation**

A Generation-2 technology that can inspect a repository, edit files, run commands and tests, observe errors, and iterate. The developer retains task selection, specification, decomposition, and verification.

**Activation**

A language is activated when the best available production mode yields nonnegative certainty-equivalent surplus.

**Activation band**

For an unfamiliar language, the interval of opportunity values that are too low for solo or conversational production but high enough for delegated production:

\[
T^D_{ikt}\leq \theta_{ikt}<T^S_{ikt}=T^1_{ikt}.
\]

See Proposition 2 and Equation (8), printed pp. 13–14.

## 3. Mechanism in plain English

Suppose a developer is very capable at software design and project management, knows Python well, but has little Rust-specific execution skill.

**Without AI:** She must personally translate her design into Rust, understand compiler errors, debug ownership problems, and verify the implementation. The project must be sufficiently valuable to compensate for weak Rust skill, uncertainty, and entry costs.

**With conversational AI:** ChatGPT might explain borrowing rules or generate a Rust snippet. But the developer must still understand, integrate, run, debug, and verify it. In the paper’s model, conversational assistance is valuable in proportion to existing language skill. For an unfamiliar language, that value is no greater than the interaction cost, so the entry threshold does not move.

**With Claude Code:** The developer can specify the desired behavior while the agent examines the repository, edits Rust files, runs the compiler and tests, reads failures, and iterates. The developer still bears specification and verification responsibilities, but she need not personally perform all language-specific execution. If agent competence and avoided execution risk outweigh verification, compute, and residual-error costs, the Rust project becomes feasible.

## 2. Productivity and knowledge distinctions

The model deliberately separates:

- **General developer ability:** \(a_i\), portable across languages.
- **Language-specific execution knowledge:** \(s_{ikt}\).
- **Latent developer-language match:** \(\mu_{ik}\), imperfectly known.
- **Opportunity value:** \(\theta_{ikt}\), the value/productivity of the particular language-month opportunity.
- **Conversational assistance:** \(\lambda s\), which scales with existing language skill.
- **Delegated execution:** \(\delta a z(A)\), which scales with general ability and agent competence.

This separation is what allows agentic AI to help a strong general developer even when \(s\) is low.

## 3. Certainty equivalents

The paper assumes CARA utility,

\[
u(y)=-e^{-\rho y}.
\]

For a Normal payoff \(Y\sim N(m,\sigma^2)\), Appendix A derives:

\[
CE=m-\frac{\rho\sigma^2}{2}.
\]

See Equations (14)–(15), p. 58.

Suppressing \(i,k,t\), the three mode surpluses are:

\[
V^S
=
\theta+s\bar\mu-\frac{\rho s^2}{2\tau}-b,
\tag{1}
\]

\[
V^C
=
V^S+\lambda s-r^C,
\tag{2}
\]

and

\[
V^D
=
\theta+(1-\delta)s\bar\mu+\delta a z(A)
-\phi(a,s)-r^D-b
-\frac{\rho}{2}
\left[
\frac{(1-\delta)^2s^2}{\tau}
+\sigma_D^2(a,s,A)
\right].
\tag{3}
\]

The paper’s extracted typography places the common \(\rho/2\) risk penalty over the human-match variance plus residual delegated-error variance; this interpretation is also confirmed by Appendix A’s threshold and \(B\) algebra.

## 4. Developer’s choice problem

There is no continuous effort choice in the core model. The developer chooses the best available discrete production mode:

\[
V^g_{ikt}
=
\max_{m\in M^g} V^m_{ikt}.
\]

She activates language \(k\) if and only if:

\[
Z^g_{ikt}
=
\mathbf 1\{V^g_{ikt}\geq0\}.
\]

Monthly language breadth is:

\[
N^g_{it}=\sum_k Z^g_{ikt}.
\]

The optimization can equivalently be written as choosing \(m\in M^g\cup\{\text{do not enter}\}\), where non-entry yields zero.

## 5. Endogenous versus exogenous objects

**Endogenous**

- production mode \(m\);
- entry/activation \(Z^g_{ikt}\);
- active-language set;
- monthly language count \(N^g_{it}\);
- first-use and cumulative-language outcomes;
- in the learning extension, updated posterior beliefs.

**Exogenous or predetermined in the core static problem**

- \(s,a,\bar\mu,\tau,\theta,b,\rho\);
- AI parameters \(\lambda,r^C,\delta,A,z,\phi,r^D,\sigma_D^2\);
- available menu \(M^g\).

The delegated share \(\delta\) is a technological parameter, not an optimized choice in the presented core model.

## 6. Main assumptions

**Assumption 1: augmentation requires a foothold**

For unfamiliar languages:

\[
\lambda s-r^C\leq0.

For familiar languages with skill \(\bar s\):

\[
\lambda\bar s-r^C>0.
\]

This assumption is essential to the claim that conversational AI does not move the unfamiliar-language threshold on impact.

**Assumption 2: verification technology**

\[
\phi_a<0,\qquad \phi_s\leq0,

and

\[
\frac{\partial\sigma_D^2}{\partial a}\leq0,\qquad
\frac{\partial\sigma_D^2}{\partial s}\leq0,\qquad

\[
B=T^S-T^D>0

and positive probability mass of \(\theta\) in \([T^D,T^S)\).

# Part D — Baseline without AI

Solo production is feasible if:

\[
V^S
=
\theta+s\bar\mu-\frac{\rho s^2}{2\tau}-b
\geq0.
\]

Rearranging:

\[
\theta\geq
b-s\bar\mu+\frac{\rho s^2}{2\tau}.
\]

Define:

\[
T^S
\equiv
b-s\bar\mu+\frac{\rho s^2}{2\tau}.
\tag{4}
\]

Thus:

\[
Z^S=\mathbf 1\{\theta\geq T^S\}.
\]

A developer does not enter an unfamiliar language when the opportunity value cannot compensate for:

- activation cost \(b\);
- low expected language-specific output \(s\bar\mu\);
- risk from uncertain developer-language match.

Comparative statics:

\[
\frac{\partial T^S}{\partial b}=1,
\qquad
\frac{\partial T^S}{\partial \bar\mu}=-s,
\qquad
\frac{\partial T^S}{\partial \rho}=\frac{s^2}{2\tau}>0,
\]

\[
\frac{\partial T^S}{\partial \tau}
=
-\frac{\rho s^2}{2\tau^2}<0,
\]

and

\[
\frac{\partial T^S}{\partial s}
=
-\bar\mu+\frac{\rho s}{\tau}.
\]

The effect of skill is therefore algebraically ambiguous unless expected productivity dominates the additional exposure to match risk:

\[
\bar\mu>\frac{\rho s}{\tau}.
\]

Formally, the solo language frontier is:

\[
\mathcal F_i^S(t)
=
\{k:\theta_{ikt}\geq T^S_{ikt}\}.
\]

# Part E — Conversational AI

Conversational AI adds the deterministic surplus:

\[
\lambda s-r^C.
\]

Hence:

\[
V^C=V^S+\lambda s-r^C.
\]

It therefore:

- increases productivity in proportion to existing language skill;
- does **not** raise \(s\) itself;
- does not change posterior knowledge or precision;
- does not reduce the variance term;
- incurs interaction cost \(r^C\);
- changes the threshold only when \(\lambda s>r^C\).

The conversational threshold is:

\[
T^C=T^S-(\lambda s-r^C).
\]

Because the developer can still work solo, the effective Generation-1 threshold is:

\[
T^1
=
\min\{T^S,T^C\}
=
T^S-\max\{0,\lambda s-r^C\}.
\tag{5}
\]

For a familiar language, Assumption 1 gives:

\[
\lambda\bar s-r^C>0
\quad\Rightarrow\quad
T^1<T^S.
\]

Conversational AI therefore generates an intensive-margin gain.

For an unfamiliar language:

\[
\lambda s-r^C\leq0
\quad\Rightarrow\quad
T^1=T^S.
\]

Thus conversational AI does not activate unfamiliar languages **under Assumption 1**. This is not a general technological theorem; it is a maintained restriction of this model.

# Part F — Agentic delegation

## 1. Distinguishing technology

Agentic AI adds a new mode in which:

- the agent executes share \(\delta\) of the language-specific work;
- delegated productivity is \(\delta a z(A)\);
- only share \(1-\delta\) of human language-specific execution remains;
- human-match variance falls by the square of the retained share;
- delegation creates verification cost, compute cost, and residual agent-error variance.

The central distinction is therefore the **locus of execution**, not merely model quality.

## 2. Delegated problem and threshold

Delegation is selected when it gives the highest nonnegative surplus:

\[
V^2=\max\{V^S,V^C,V^D\}.
\]

Starting from Equation (3):

\[
\theta+(1-\delta)s\bar\mu+\delta az(A)
-\phi-r^D-b
-\frac{\rho}{2}
\left[
\frac{(1-\delta)^2s^2}{\tau}
+\sigma_D^2
\right]\geq0.
\]

Move every term except \(\theta\) to the right:

\[
\theta\geq
b-(1-\delta)s\bar\mu-\delta az(A)
+\phi(a,s)+r^D
+\frac{\rho}{2}
\left[
\frac{(1-\delta)^2s^2}{\tau}
+\sigma_D^2(a,s,A)
\right].
\]

Define:

\[
T^D
\equiv
b-(1-\delta)s\bar\mu-\delta az(A)
+\phi(a,s)+r^D
+\frac{\rho}{2}
\left[
\frac{(1-\delta)^2s^2}{\tau}
+\sigma_D^2(a,s,A)
\right].
\tag{6}
\]

The post-agent effective threshold is:

\[
T^2=\min\{T^1,T^D\}\leq T^1.
\]

The agent expands the feasible set when:

\[
T^D<T^1
\]

and an opportunity falls between those thresholds.

## 3. Human constraint relaxed

The agent relaxes the need for the developer to personally perform all language-specific execution. It does not eliminate:

- general problem-solving ability;
- specification;
- task decomposition;
- verification;
- all residual execution risk.

Frontier expansion requires both a sufficiently favorable delegation technology and an opportunity in the newly feasible interval.

# Part G — Activation band

For an unfamiliar language, Assumption 1 implies:

\[
T^1=T^S.
\]

Define the threshold reduction:

\[
B\equiv T^1-T^D=T^S-T^D.
\]

Substituting Equations (4) and (6):

\[
\begin{aligned}
B
&=
b-s\bar\mu+\frac{\rho s^2}{2\tau}\\
&\quad-
\left[
b-(1-\delta)s\bar\mu-\delta az(A)
+\phi+r^D
+\frac{\rho}{2}
\left(
\frac{(1-\delta)^2s^2}{\tau}
+\sigma_D^2
\right)
\right].
\end{aligned}
\]

Cancel \(b\), collect expected-output terms, and collect risk terms:

\[
B
=
\delta[az(A)-s\bar\mu]
-\phi(a,s)-r^D
+
\frac{\rho}{2}
\left[
\frac{(2\delta-\delta^2)s^2}{\tau}
-\sigma_D^2(a,s,A)
\right].
\tag{7}
\]

Interpretation:

- \(\delta[az(A)-s\bar\mu]\): expected execution substitution;
- \(-\phi-r^D\): verification and compute costs;
- the final term: reduced human-match risk minus added agent-error risk.

If \(B>0\), then \(T^D<T^S\), and Proposition 2 gives:

\[
Z^2-Z^1
=
\mathbf 1\{T^D\leq\theta<T^S\}.
\tag{8}
\]

The activation probability is:

\[
F(T^S)-F(T^D).
\]

Conceptual number line:

```text
θ < Tᴰ                    Tᴰ ≤ θ < T¹ = Tˢ                 θ ≥ T¹ = Tˢ
inactive under both       activation band                  active under both
Z¹ = Z² = 0               Z¹ = 0, Z² = 1                  Z¹ = Z² = 1
```

The width is:

\[
W=T^S-T^D=B
\]

when \(B>0\); economically, the usable width is \(\max\{0,B\}\).

Important comparative statics include:

\[
\frac{\partial B}{\partial r^D}=-1,
\qquad
\frac{\partial B}{\partial \phi}=-1,
\]

\[
\frac{\partial B}{\partial \sigma_D^2}
=
-\frac{\rho}{2}<0,
\]

\[
\frac{\partial B}{\partial \bar\mu}
=
-\delta s<0.
\]

Higher solo productivity shrinks the band because more opportunities were already feasible.

Holding the functional arguments fixed:

\[
\frac{\partial B}{\partial z}
=
\delta a>0.
\]

For ability,

\[
\frac{\partial B}{\partial a}
=
\delta z(A)-\phi_a
-\frac{\rho}{2}\frac{\partial\sigma_D^2}{\partial a}
\geq0
\]

under Assumption 2 and \(z(A)\geq0\), with strictness under at least one strict component.

For agent capability,

\[
\frac{\partial B}{\partial A}
=
\delta a z'(A)
-\frac{\rho}{2}\frac{\partial\sigma_D^2}{\partial A}
\geq0.
\]

For precision:

\[
\frac{\partial B}{\partial\tau}
=
-\frac{\rho(2\delta-\delta^2)s^2}{2\tau^2}<0.
\]

Greater precision shrinks the delegation band because it reduces the solo mode’s risk disadvantage.

The derivative with respect to \(\delta\) is not unambiguously positive without additional restrictions:

\[
\frac{\partial B}{\partial\delta}
=
az(A)-s\bar\mu
+
\frac{\rho(1-\delta)s^2}{\tau},
\]

if \(\phi\) and \(\sigma_D^2\) do not themselves vary with \(\delta\).

Proposition 2 appears on printed pp. 13–14; its proof is on p. 60.

# Part H — Frontier expansion

Define:

\[
\mathcal F_i^g(t)
=
\{k:V^g_{ikt}\geq0\}
=
\{k:\theta_{ikt}\geq T^g_{ikt}\}.
\]

Then:

**No AI**

\[
\mathcal F_i^S(t)
=
\{k:\theta_{ikt}\geq T^S_{ikt}\}.
\]

**Conversational menu**

\[
\mathcal F_i^1(t)
=
\{k:\theta_{ikt}\geq T^1_{ikt}\}.
\]

It expands the familiar-language intensive margin when \(\lambda s-r^C>0\), but under Assumption 1 does not alter unfamiliar-language entry.

**Agentic menu**

\[
\mathcal F_i^2(t)
=
\{k:\theta_{ikt}\geq\min(T^1_{ikt},T^D_{ikt})\}.
\]

Because \(M^1\subset M^2\):

\[
V^2_{ikt}\geq V^1_{ikt},
\qquad
Z^2_{ikt}\geq Z^1_{ikt},
\qquad
N^2_{it}\geq N^1_{it}.
\]

This is Proposition 1, p. 13, proved on pp. 59–60.

Strict extensive-margin expansion requires at least one language satisfying:

\[
T^D_{ikt}<T^1_{ikt}
\]

and

\[
T^D_{ikt}\leq\theta_{ikt}<T^1_{ikt}.
\]

The distinction matters economically because a productivity gain within known languages affects how much a developer produces, whereas activation changes developer-project matching, the range of technologies a worker can operate, and the return to language-specific versus general verification ability.

# Part I — Comparison with Aouad, Lykouris, and Zhong

This comparison is based on the characterization supplied in the question, not on a separate inspection of Repository 1.

In Aouad, Lykouris, and Zhong, AI enters as a productive input that substitutes for human implementation effort. The main adjustment margin is therefore an interior effort allocation:

\[
AI\uparrow \quad\Rightarrow\quad \text{required human implementation effort}\downarrow.
\]

Here, the critical constraint is a **discrete language-entry condition**:

\[
V_{ikt}\geq0.
\]

Conversational AI adds productivity proportional to existing language-specific skill, while agentic AI adds a distinct delegated-execution mode whose output depends on \(a_i z(A)\). This changes the minimum opportunity value required to enter language \(k\):

\[
T^1\longrightarrow T^2=\min\{T^1,T^D\}.
\]

Thus the exact modeling difference is:

- Aouad et al.: AI substitutes inside a fixed feasible task or production set.
- Quispe–Xu: delegation can relax a language-specific participation constraint and expand the feasible set itself.

The conclusions are complementary. Within any activated language, agentic AI could also reduce human execution effort. Quispe–Xu isolate the additional extensive margin that arises when the threshold is crossed.

# Part J — Empirical design and results

## 1. Data and sample

The panel runs from January 2024 through April 2026. Adoption is defined as a developer’s first commit containing a machine-readable:

> `Co-Authored-By: Claude`

trailer.

Early adopters, April–September 2025, form the treated cohorts. Later adopters, October 2025–January 2026, serve as not-yet-treated controls before their own adoption.

The main estimation sample has 5,346 developers and 149,688 developer-month observations. Languages are recovered from commit-level changed-file paths using GitHub Linguist.

## 2. Outcomes

Primary outcomes:

\[
N_{it}
\]

Number of distinct programming languages used in month \(t\).

\[
N^{new}_{it}
\]

Languages appearing for the first time in the developer’s observed history since January 2024.

\[
C_{it}
\]

Cumulative number of distinct languages observed through month \(t\).

\[
H_{it}=-\sum_k p_{itk}\log p_{itk}
\]

Shannon entropy of changed files across programming languages.

Diagnostic outcomes:

- repositories per month;
- commits per month.

See pp. 20–22.

The paper estimates group-time effects:

\[
ATT(g,t)
=
E[Y_{it}(g)-Y_{it}(0)\mid G_i=g].
\tag{11}
\]

It uses the doubly robust Callaway–Sant’Anna staggered-adoption estimator with:

- not-yet-treated comparisons;
- varying base period;
- one-month anticipation;
- 1,000 multiplier-bootstrap iterations;
- developer-clustered standard errors.

Dynamic effects are aggregated by event time using Equation (12), and the simple post-treatment ATT uses Equation (13). See pp. 23–27.

- Increase in monthly languages: expansion of the active production set.

- common calendar-time shocks;

- mechanical inclusion of the adoption commit;

It does not rule out a project shock that simultaneously causes:

- adoption of Claude Code;
- increased activity;
- entry into a new language.

# Part K — Skeptical referee checks

## Theory check 1: Does frontier expansion truly require an agent?

No—not as a purely mathematical matter.

Suppose conversational AI instead provides gain \(G_C(s)\). Its threshold is:

\[
T^C=T^S-G_C(s).
\]

If \(G_C(s)>0\), then any opportunity satisfying:

\[
T^C\leq\theta<T^S
\]

is activated by conversational AI.

In the paper:

\[
G_C(s)=\lambda s-r^C.
\]

Thus sufficiently strong conversational assistance activates an unfamiliar language whenever:

\[
\lambda s-r^C>0.
\]

The paper excludes this by Assumption 1:

\[
\lambda s-r^C\leq0
\quad\text{for unfamiliar languages}.
\]

Likewise, any ordinary additive productivity shock \(\Delta>0\) changes the solo threshold to:

\[
T^{S,\Delta}=T^S-\Delta,
\]

and activates opportunities in:

\[
[T^S-\Delta,T^S).
\]

Therefore frontier expansion is not logically unique to agents. The agent-specific result arises from a combination of:

1. conversational gains being constrained to scale with existing skill;
2. unfamiliar-language conversational gains being assumed nonpositive net of interaction cost;
3. the delegated mode producing output through general ability and agent competence;
4. delegation reducing reliance on language-specific human execution.

The economically distinctive feature is the **form of the technology**, not the abstract fact that productivity rises.

## Theory check 2: Threshold ordering

The ordering \(T^D<T^S\) is not automatic. It requires:

\[
B>0.
\]

The activation band is empty if:

\[
B\leq0,
\]

or if the opportunity distribution places no mass between the thresholds.

Thresholds need not be interior to the support of \(\theta\). For meaningful three-region behavior, one needs:

\[
\underline\theta<T^D<T^S<\overline\theta.
\]

The paper does not impose that global support condition. Proposition 2 only needs \(B>0\) to identify the formal interval; a positive activation probability additionally needs:

\[
F(T^S)-F(T^D)>0.
\]

If \(T^D\geq T^1\), the developer simply ignores delegation because:

\[
T^2=\min\{T^1,T^D\}=T^1.
\]

## Empirical check: endogenous adoption

### Authors’ acknowledged concerns

The authors explicitly acknowledge:

- voluntary adoption;
- adoption triggered by an unfamiliar-language project;
- treatment timing measured slightly late;
- possible private or untraced prior agent use;
- inability to detect AI use with no commit signature;
- cumulative-language pre-trends;
- imperfect ability proxy;
- inability of outcome-side robustness checks to resolve selection into timing.

### Additional referee interpretation

Even clean pre-trends do not establish that the \(e=0\) innovation is exogenous. A discrete project shock can arrive at \(e=0\) without generating earlier differential trends.

The persistent unassisted-language effects weaken a narrowly mechanical “first commit only” explanation, but they do not eliminate a persistent new-project shock. Consequently, the estimates should remain associational absent an instrument, rollout discontinuity, pricing shock, or randomized access.

# Part L — Internal errors or overstatements

I did not find a clear algebraic error in the threshold derivations or formal proofs. I did find several qualifications worth noting.

## 1. “Threshold does not require language-specific skill”

Appendix B, p. 63, describes \(T^D\) as not requiring language-specific skill. Strictly, Equation (6) still depends on \(s\) through:

- retained human output \((1-\delta)s\bar\mu\);
- verification cost \(\phi(a,s)\);
- human-match variance;
- residual agent-error variance.

The defensible interpretation is that delegation does not require a **positive conversational foothold** or that it can remain valuable at very low \(s\). Saying it is independent of language-specific skill is stronger than the algebra.

This is an interpretive overstatement, not a faulty proposition.

## 2. “Reduction is larger” versus “weakly larger”

After Equation (7), the paper says the threshold reduction is larger for higher-ability developers and more capable agents. Assumption 2 generally supports weak monotonicity. Strict monotonicity additionally requires at least one strict channel, such as:

\[
z(A)>0,\quad z'(A)>0,\quad \phi_a<0,
\]

or a strictly declining residual variance at the relevant point.

For ability, \(\phi_a<0\) supplies strictness if differentiability and the printed assumption apply. For capability \(A\), the text says \(z(A)\) is increasing, but if “increasing” is interpreted weakly and residual variance is locally flat, strict expansion is not guaranteed. This is at most an omitted strictness qualification.

## 3. Proposition 2 is conditional, not universal

The proposition correctly assumes \(B>0\). Informal statements that agentic tools “create” an activation band should always be read subject to:

\[
\delta[az(A)-s\bar\mu]
+\frac{\rho}{2}
\left[
\frac{(2\delta-\delta^2)s^2}{\tau}-\sigma_D^2
\right]
>
\phi+r^D.
\]

High verification costs, compute costs, or residual error can make delegation inferior.

## 4. Cumulative-language evidence

The paper responsibly notes that four of five pre-period cumulative-language coefficients are significant. Claims based on this outcome are therefore descriptive. The main conclusion is better supported by the monthly language count, first-use flow, and entropy.

## 5. Specialist comparison

The paper says the within-ability specialist gap “cannot be an artifact of activity volume.” The double sort substantially addresses the mechanical correlation, but splitting activity at the median does not make volume identical within cells. “Less likely to be driven by broad activity differences” would be more precise. This is a referee-level qualification, not a demonstrated error.

# Part N — Oral-exam preparation

## 1. Five-minute explanation

The paper asks whether agentic coding assistants expand a developer’s programming-language production frontier. The key idea is that conventional conversational AI and agentic AI operate through different margins.

A developer has general ability \(a_i\), such as the ability to specify and verify a project, and language-specific execution skill \(s_{ikt}\). Without an agent, production in language \(k\) is worthwhile only if the opportunity value \(\theta_{ikt}\) exceeds a threshold \(T^S_{ikt}\). That threshold rises with activation costs and risk and falls with expected language-specific productivity.

Conversational AI contributes \(\lambda s-r^C\). Because its usefulness scales with existing language skill, it lowers the threshold for familiar languages. Under the paper’s foothold assumption, however, its net value is nonpositive in an unfamiliar language, so the unfamiliar-language threshold remains \(T^S\).

Agentic AI adds a new production mode. The agent executes share \(\delta\) of the work, generating output \(\delta a_i z(A)\), while the developer specifies and verifies. Delegation reduces exposure to the uncertain human-language match but adds verification costs, compute costs, and residual agent-error risk.

The delegated threshold is \(T^D\). If \(T^D<T^S\), opportunities between the thresholds form an activation band. Those projects were infeasible before the agent but feasible afterward. This expands the developer’s production frontier without necessarily increasing the developer’s unaided language skill.

Empirically, the authors construct a 28-month panel of 5,346 GitHub developers using more than 3.15 million commits and 57.2 million changed files. Claude Code adoption is dated by the first Claude coauthor trailer. A doubly robust staggered event study compares early adopters with later, not-yet-treated adopters.

At adoption, monthly active languages rise by 2.53 relative to a 0.90 baseline; newly used languages rise by 1.19; entropy rises by 0.38; and cumulative languages rise by 1.60. Much of the effect survives removing the first-Claude language and all Claude-coauthored commits. Specialists show larger first-use responses than generalists.

The major limitation is selection: developers may adopt Claude precisely when starting unfamiliar-language projects. The authors therefore interpret the estimates as robust event-time associations, not definitive causal effects.

## 3. Fifteen likely oral-exam questions

1. **What is the paper’s main economic object?**  
   The developer’s language-production frontier, not unaided language skill.

2. **What is the key distinction between conversational and agentic AI?**  
   Conversational AI supplies suggestions the human executes; agentic AI performs delegated execution.

3. **What is \(s_{ikt}\)?**  
   Language-specific execution skill, distinct from general ability.

4. **What is \(a_i\)?**  
   Language-invariant ability to specify, decompose, and verify tasks.

5. **What determines solo entry?**  
   \(\theta_{ikt}\geq T^S_{ikt}\).

6. **What is the solo threshold?**  
   \(T^S=b-s\bar\mu+\rho s^2/(2\tau)\).

7. **How does conversational AI enter?**  
   Through deterministic net gain \(\lambda s-r^C\).

8. **Why does conversational AI not activate unfamiliar languages?**  
   Because Assumption 1 imposes \(\lambda s-r^C\leq0\) there.

9. **What is delegated productivity?**  
   \(\delta a_i z(A)\).

10. **What costs does delegation create?**  
    Verification cost, compute cost, and residual-error risk.

11. **What is the activation band?**  
    \([T^D,T^S)\) for unfamiliar languages when \(T^D<T^S\).

12. **Why is frontier expansion weakly guaranteed?**  
    Agent adoption expands the menu; the developer may ignore the agent.

13. **When is expansion strict?**  
    When at least one opportunity lies in the activation band.

14. **What is the cleanest empirical counterpart of activation?**  
    The newly-used-language flow.

    Adoption timing may be jointly determined with new-project or unfamiliar-language shocks.

## 4. Five threshold-understanding questions

1. **If \(\lambda s-r^C>0\) for an unfamiliar language, what happens?**  
   Conversational AI lowers its threshold and can activate it; the paper’s qualitative separation would no longer hold for that language.

2. **Can \(T^D>T^S\)?**  
   Yes. The developer then ignores delegation, so \(T^2=T^1\).

## 7. Aouad–Lykouris–Zhong versus Quispe–Xu

Based on the modeling characterization in your prompt:

### Aouad–Lykouris–Zhong

AI is a substitutable productive input within an already selected task. AI and human implementation effort jointly produce the task, so better or cheaper AI changes the conditional input choice:

\[
AI\uparrow
\quad\Longrightarrow\quad
\text{human implementation effort}\downarrow.
\]

The main margin is an **interior input-substitution margin**, conditional on performing the task.

### Quispe–Xu

The developer first faces a participation/entry constraint:

\[
\max_{m\in M^g}V^m_{ik,t}\geq0.
\]

Agentic AI adds a new production mode:

\[
M^1=\{S,C\}
\quad\longrightarrow\quad
M^2=\{S,C,D\}.
\]

The delegated mode has a separate threshold \(T^D\). If:

\[
T^D<T^1,
\]

then opportunities satisfying:

\[
T^D\leq\omega<T^1
\]

become feasible.

The precise distinction is therefore:

| Aouad–Lykouris–Zhong | Quispe–Xu |
|---|---|
| AI substitutes for human implementation inside a task | AI adds a delegated mode to the production menu |
| Task is already in the feasible/selected set | Some language-task opportunities initially fail an entry constraint |
| Main endogenous margin: amount of human effort | Main endogenous margin: whether the language becomes active |
| Main result: AI input rises, human effort falls | Main result: effective entry threshold can fall and the frontier can expand |

These are complementary mechanisms. A delegated agent may reduce human effort inside an activated task, while also enabling entry into tasks that were previously outside the feasible set.
